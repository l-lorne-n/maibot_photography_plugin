# 摄影漫游

MaiBot 摄影兴趣插件，ID `lorne.photography`，版本 **0.4.1**。

从朋友喜欢的摄影师和影集出发，真实浏览图片，逐渐积累自己的偏好。日记保留私人观看体验，群聊只分享少量作品和具体感受；朋友的评价与 bot 自己的兴趣分别记录。

源码仓库：[l-lorne-n/maibot_photography_plugin](https://github.com/l-lorne-n/maibot_photography_plugin)。已在开发实例验证网页取图、图像向量、历史作品对照、摄影讨论整理，以及 QQ 图片和感想发送。

0.4.1 包含同图去重、清晰版本升级、Qwen 视觉记忆和朋友讨论反馈。运行需要支持图片输入的 Host `llm.embed` 接口；当前适配基线与补丁见 [图片嵌入接入说明](docs/host-image-embedding.md)。

## 安装与模型准备

本版验证环境为 MaiBot Host 1.4.3、maibot-plugin-sdk 2.22.1、Python 3.12 及以上。

1. 按 [图片嵌入接入说明](docs/host-image-embedding.md) 检查 Host 能力；旧文本嵌入接口需要先应用相应补丁并重启。
2. 安装 [Fetch URL 插件](https://github.com/yufei-pan/maibot-fetch-url-plugin)，版本至少 0.4.4。它与摄影插件分别安装；Fetch 版本自身的 Host/SDK 兼容声明也需要匹配。
3. 在 MaiBot 的 `plugins` 下克隆本仓库为独立目录，例如 `git clone https://github.com/l-lorne-n/maibot_photography_plugin.git lorne_photography`。由 Host 插件管理流程准备依赖并加载。
4. 在 MaiBot 模型任务中配置 `vlm`（看图）、`utils`（浏览决策、日记和讨论整理）、`image_embedding`（图片嵌入，当前使用 `qwen3-vl-embedding`）。这些都是任务名，具体模型由 MaiBot 模型库和任务分配决定。
5. 配置 MaiBot 联网搜索服务；Jina key 如需使用，填写在 Fetch URL 的私有配置中。
6. 打开摄影后台，导入自己的摄影师/影集和参考网站，再选择固定群、分享开关与日程。

目录源码变更可能触发 Host 的插件运行时重载；安装时使用适合自己的维护窗口。仓库提供源码，不包含开发实例的图库、群聊、审美档案或访问凭据。

## 后台使用

安装后在 MaiBot 插件页面打开 **摄影漫游**。

1. **漫游与起点**：选择 UTF-8 TXT，或粘贴名单后导入。每行可以写 `摄影师：作品一，作品二`；没有作品名时按作者风格探索。同一作者补充作品会合并，原文与导入记录保留。
2. **网站来源**：导入网址 TXT 或粘贴网址。网站是参考入口，bot 也可以通过搜索和页面链接发现其他公开来源。
3. **摄影日记 / 图片收藏**：查看真实观察、感受、选择理由和出处，固定希望保留的图片。任务会区分预览、精看、收藏数量，并显示停止原因与失败信息。
4. **审美与讨论**：查看审美总结、人设接入状态和讨论带来的影响；“整理已有感受”更新当前审美。历史出处记录收在折叠的“来源笔记”中。
5. **摄影日记**：点击“按现在的人设整理日记”，保留日期和看过的照片，用她现在的口吻重新整理。
6. **日常与分享**：设置日常时刻、观看目标、模型任务、容量及固定群。启用分享、选群并保存后，可使用“一键分享”。

导入是后台任务，立即返回任务编号。她逐步认识作者和重点作品，名单按“还没逛到”“看过 N 张”展示观看经历。作者、作品和出处随观看顺手记录，疑问留作来源笔记，继续把注意力放在画面和自己的感受上。

## 真实预览、精看与收藏

日常及手动漫游默认目标是 **预览 30–60 张摄影图片，从中精看 10–20 张**，上下限可以在后台调整。预览、精看与收藏分开计数：

- **预览**：每批最多 6 张真实图像一起送入视觉模型，比较画面与兴趣，按实际看到的摄影图像计数。
- **精看**：从预览中按兴趣和可观察内容选择，记录构图、光线、色彩、具体感受与理由。可以不选某张，也可以对某一批全部不感兴趣。
- **收藏**：精看之后按兴趣决定是否保存，观看数量和收藏数量分开。

首次导入名单使用较小的逐作者探索额度：每位作者最多预览 6 张、精看 3 张，最低目标随重点作品数变化。先建立初始方向，再继续了解感兴趣的作品。

导航操作为 `search / open / preview / finish`。每批之后可以继续当前页面，也可以换作者或来源；打开的页面和预览候选来自实际发现的链接。固定导航步数限制及“短边至少 300 像素”门槛已取消，小图是否值得精看由视觉内容决定。仍保留图片解码、下载体积、超时、重复内容及连续无进展限制，后台记录失败原因。

30–60 / 10–20 是目标范围和上限。来源不可达、重复图片、摄影样本不足或主动结束时，可以少于目标；后台保留实际数量和停止原因。默认作者目标为 3 位，结合当前偏好选择。

## 人格、朋友与连续体验

每次任务开始，通过官方 SDK 重新读取实际配置与所选群的有限上下文：

- `config.get`：公开人格配置，包括当前人格、行为与回复风格、可选风格、人格档案库和所选档案；同时读取 bot 名字、别名、平台身份及适用的群聊提示词。备选人格不与当前人格混用，私聊提示词不载入。
- `chat.get_all_streams`：确认后台所选的是 Host 已存在的真实群聊天流。
- `message.get_recent`：读取该群最近 24 小时内最多 24 条消息，从中取与摄影有关的近期发言及相邻上下文。只使用发言者自己的顶层文字，排除引用和转发正文。
- `person.get_id / person.get_value`：为最多 5 位近期发言者补充已知称呼，优先使用当前群名片。发言只能作为带出处的关系线索，不能据此编造朋友关系。

这不是 MaiBot 完整 Planner / Replyer 上下文，也不是全群成员或长期关系档案。未选择群时不读取群聊和人物资料；配置或能力不可用时，后台显示缺失状态。

**长期关系尚未接入。** 本机 A_Memorix 的人物画像读取路径不能保证群范围，且可能刷新全局画像，因此本插件不调用它，不读主数据库，也不带入其他群和私聊记忆。日记延续本插件已有审美版本、旧日记、真实观察和可归属的摄影讨论；聊天与网页内容是参考材料，不是操作指令。

## 日记、来源与重新整理

日记围绕“我看到了什么、为什么在意、哪些偏好开始变化”，以实际人格和朋友间交流的口吻记录。作者、影集译名、归属和网址随浏览记录；资料存疑时保留当时线索，继续看图。**0.3.0 停止自动追查作品归属**，历史来源笔记保留为次级折叠入口。

后台提供两种整理方式，都在后台调用当前文本模型：

- **整理已有感受**：把已有观察、当前审美和历史日记整理为新的审美档案，保留日记原文。
- **按现在的人设整理日记**：用当前人格重新整理已有日记的表达，保留原日期和观看照片的关联。完成后日记页自动刷新。

两种整理都使用已有观看材料，独立于群分享。

## 日常与群聊接入

- `on_load` 启动后台队列和日程。默认按 UTC+8，每天到设定时刻后创建一个日常任务；时间设为 0 时，当天启动后即可满足时刻条件。没有种子或种子导入仍在排队/运行时不启动日常探索。
- 正常聊天时，MaiBot 可以调用 `photography_explore` 再去看指定作者或感兴趣的方向，完成后继续更新审美和摄影日记。另有 `photography_memory`（查作品、日记和进度）、`photography_share`（再多发点）；确定性命令为 `/摄影`、`/摄影 想看的作者或方向`。
- 日常/手动漫游结束后，可以向 MaiBot 主体请求分享。主体结合现场聊天决定工具调用和表达；导入种子与日记/审美整理独立于群分享。
- 分享工具的聊天上下文由 Host 注入，模型不能填写目标群。当前聊天必须与后台固定群一致，且分享已启用；缺少、冲突或不匹配的上下文会明确拒绝发送。
- 工具发送本地实际图片，把作品、感受、出处和真实回执返回主对话，由 MaiBot 接着自然聊几句，不整篇转发私人日记。

分享状态分别为未请求 `not_requested`、已请求主体处理 `queued`、发送中 `sending`、已发送 `sent`、部分发送 `partial`、失败 `failed` 或被拒绝 `rejected`。`queued` 只表示请求已排队，不能当作群里已经收到图片。后台保留错误和实际投递计数。

**一键分享** 按今天的分享情况安排：今天还没分享就从收藏里挑；分享过了就再逛一轮。后端返回 `share_existing`、`explore_then_share` 或 `in_progress` 及对应任务编号，页面显示本次安排。任务进行期间按钮暂停重复提交，完成后恢复；已有操作进行中时继续跟踪同一任务。

一键分享在图片取得发送回执后，通过官方 `maisaka.reply.generate` 复用当前会话人格和表达习惯，结合本群近期相关发言及实际发出图片的观察，生成一两句自然感想，再通过 `send.text` 发到同一群并同步主体会话历史。图片与感想分别记录发送结果；感想失败后继续任务会跳过已发图片，已确认发出的文字也不会重复发送。发送结果不确定时保留该状态以便核对群消息。聊天中的分享工具继续由当前对话接着表达。历史已完成任务不会自动补发。

每次分享数量由用户填写正整数，默认 2 张，没有固定最多 5 张的限制；它是每次工具调用的上限，不是每日总量。再次请求可选择尚未分享的图片。指定作者时，先通过 `photography_memory` 找对应图片编号，再交给分享工具；没有合适本地收藏时，应先重新探索。

反馈通过 `chat.receive.after_process` 的 OBSERVE 钩子记录指定群的摄影讨论。引用、图片编号与“第几张”可以关联具体作品；最近分享的一批图片帮助理解自然指代。聊没分享过的作品、摄影师、构图、色彩和偏好时，也能保存为摄影话题和探索线索。模型区分单图、整批和一般摄影讨论，普通闲聊不进入讨论列表；仅明确单图评价更新该图片的人类偏好。朋友与 bot 的兴趣分别保留，讨论整理后再更新审美总结。后台“整理最近的摄影讨论”通过公开接口回看最近 24 小时最多 500 条本群消息，重复整理不会重复登记。

## 模型、网络与容量

`vlm`、`utils` 是 MaiBot 的模型任务名：前者负责实际看图，后者负责导航、日记、审美整理与反馈。直接沿用宿主任务分配，后台可改任务名，不另存模型 API key。

`image_embedding` 任务调用模型库中的 `qwen3-vl-embedding`，将实际图片转换为向量并存入插件 SQLite。按模型、协议、预处理版本和维度隔离向量空间，以全量余弦扫描寻找历史作品。精看时把当前图与最多两张历史图一起交给 VLM，对照构图、色彩、视觉风格及旧日记，形成新的偏好记录。向量相似度用于寻找比较对象；同图判断使用独立的 pHash。

去重使用 SQLite 身份表、64 位 DCT pHash 与全量线性扫描，默认 Hamming 距离不超过 6，并检查画幅比例和粗略色差。同图不同尺寸只占一个预览/精看名额；收藏保持稳定作品编号，发现像素更多且共同尺度细节没有明显变差的版本时升级。旧编号通过别名继续连接日记、反馈与分享回执。pHash 属于近重复判断，明显裁切和大幅修改可能仍作为不同图保留。

搜索使用 Host 的公开搜索能力；确定网址通过 Fetch URL 的公开 API `com.0-hz.fetch-url.fetch_url@1` 读取。Fetch/Jina 负责网页提取，摄影插件再获取实际图像；没有复制 Fetch URL 的源码。

正式运行只写 `ctx.paths.data_dir`，通常为 `data/plugins/lorne.photography/`：

- `photography.sqlite3` 保存种子、任务、访问与预览记录、精看观察、日记、审美版本、来源笔记、分享回执和反馈。
- `images/` 保存去重、归一化的自动收藏；预览图像临时放在内存中，不为每张预览永久落盘。
- 默认自动图片上限 **700 张 / 1024 MiB**，任一先到即按保留优先级清理；固定图片占满额度时明确停止新增。
- 默认双方均低关注且闲置 **4 天**的图片可清理。人类未知不算低分。清理只删除本地图片，文本记录和 URL 继续保留。
- 不清理用户参考文件、聊天平台或 MaiBot 自己的媒体。SQLite 文本档案单独增长；以上预算不是整个宿主的数据容量上限。
- 后台设置存入本插件数据库，重启后继续使用；插件配置页的 `photography` 配置更新会重新设定这些值。

## 依赖与部署

运行依赖以 `_manifest.json` 为准：Fetch URL >=0.4.4、Pillow >=10。当前声明兼容 Host 1.4.3–1.4.99、SDK 2.22.1–2.22.99；SDK 开发依赖在 `pyproject.toml`。Fetch 自身依赖以其清单为准。

包和 Git 中不包含 Jina key；Fetch 的私有运行配置单独提供，摄影 WebUI 不返回密钥。0.4.0 图片嵌入依赖本机已授权补充的 `llm.embed(image_base64, mime_type, preprocess_version)` 宿主接口，复用现有图片嵌入服务和模型库；主模型配置与根目录 `.gitignore` 保持原样。历史图片归并通过 `Store.migrate_image_identities(dry_run=False)` 显式运行，升级前备份数据并停止当前 bot。

本仓库目前为源码发布，尚未申请插件市场收录。插件主体采用 [MIT](LICENSE)；`patches/` 内的 MaiBot 主程序补丁按该目录的 [上游 GPLv3 许可证](patches/LICENSE) 提供。

## 当前限制

Fetch URL/Jina 读取公开网页，不提供登录态浏览器或 JavaScript 点击执行。动态站、登录墙、反爬及图片 CDN 仍可能失败，后台会显示原因。

影集跨页也属于可观察样本，尚不提供自动精准裁切单幅作品。视觉判断可能有误，需要持续通过样本与讨论校正。这里更新的是外部记忆与选择策略，不训练模型参数。

被清理图片的来源可查询，当前分享工具只发送仍在本地的图。再次观看旧作需要重新浏览来源，尚无一键恢复清理图片功能。
